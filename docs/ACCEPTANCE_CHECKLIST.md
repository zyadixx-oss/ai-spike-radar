## 2. الافتراضات غير المثبتة (Unverified assumptions)
1. **الانفجارات قد تكون عشوائية عديمة الذاكرة.** تصف Deriv هذه المؤشرات بأنها مُولّدة بمتوسط تكرار ثابت (≈ مرة كل N تيك). إن صحّ ذلك فلن يتفوق أي نموذج على المعدل الأساسي، وسيعرض النظام ذلك صراحة. لا نفترض العكس.
2. معدل التيك (~1/ثانية) **لا يُفترض**؛ يقاس من البيانات.
3. عتبة الانفجار k=8×σ_robust افتراضية قابلة للضبط؛ تُعرض حساسية العدّ لقيم k مختلفة.
4. تكلفة التداول الافتراضي (السبريد) غير منشورة بدقة؛ قيمة افتراضية قابلة للضبط `SIM_COST_PER_TRADE_PCT`.
5. مدى التاريخ المتاح لـ Tick عبر API محدود (غير موثّق بدقة)؛ النظام يجمع للخلف حتى يتوقف API أو حتى `MAX_BACKFILL_DAYS`، ثم يستمر لحظيًا فيتراكم التاريخ.
6. app_id=1089 هو المعرّف العام للتجربة؛ يُنصح بتسجيل app_id خاص.

## 4. حالات الفشل المحتملة ومعالجتها
| الفشل | المعالجة |
|-------|----------|
| انقطاع WebSocket | Backoff أسّي + ping + إعادة اشتراك + تعويض الفجوة من history |
| فجوة بيانات لا يمكن تعويضها | تُسجَّل في `data_gaps`، وتقسيم المقاطع يمنع الميزات/التسميات عبرها |
| رمز غير متاح/موقوف | يظهر "غير متاح" في System Health |
| فشل تدريب نموذج | المهمة تفشل بسجل الخطأ وتُعاد حتى max_attempts؛ النموذج الحالي يبقى؛ الرادار يعود رماديًا إن لم يوجد نموذج |
| فشل نموذج أثناء التوقع | يُلتقط الاستثناء، الحالة رمادي + سبب، لا يتوقف الرادار |
| توقف الخادم أثناء مهمة | Lease ينتهي ⇒ المهمة تعود للطابور |
| بيانات غير كافية | لا تدريب تحت حدود دنيا (عدد انفجارات/صفوف)؛ الحالة رمادي |
| عدم وجود قابلية للتنبؤ | النتيجة تُعرض كما هي: "لا دليل إحصائي" |
| محاولة إرسال أمر تداول | العميل يرفع `TradingForbiddenError` قبل الإرسال |

### مشكلات اكتُشفت وأُصلحت أثناء التحقق
1. **دلالة زائفة من التسميات المتداخلة:** الصفوف المتجاورة تتشارك نفس الانفجار المستقبلي فتتضخم الدلالة (المختبر "اعتمد" 129 قاعدة على بيانات عشوائية). الحل: تقييم الإشارات كمحاولات غير متداخلة + فحص زوجي/فردي. بعدها: 0.
2. **فجوة بعد إعادة الاتصال:** التيكات الحية الجديدة كانت تُخزَّن قبل السدّ فيبدأ السدّ بعد الفجوة. الحل: لقطة لآخر تيك حي عند الانقطاع + إصلاح دوري للثقوب القصيرة.
3. **تنافس GIL:** التدريب كان يتباطأ بشدة بسبب مسح كامل متكرر للتيكات عبر صفوف SQLAlchemy. الحل: تحميل سريع عبر المؤشر الخام، مسح تزايدي للانفجارات، المهام الثقيلة في عملية منفصلة، وعقد إيجار قصير مع نبض (heartbeat).
4. **مشاركة النماذج بين العمليات:** Render لا يشارك الأقراص بين الخدمات ← النماذج تُخزَّن في قاعدة البيانات (`model_artifacts`).
5. **عرض الأرقام في RTL:** القيم السالبة وفواصل الثقة كانت تنعكس ← عزل LTR لكل رقم.
6. خلل في HistGradientBoosting مع أعمدة NaN بالكامل ← محوّل يحذفها قبل التدريب.
